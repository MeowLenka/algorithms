Основное внимание уделялось работе в среде виртуализации, изучению командного интерпретатора, а также разработке программного обеспечения с использованием статических и динамических библиотек, работе с двоичными файлами и псевдографической библиотекой ncurses.

    \item Nano и Visual Studio Code -- редакторы кода.
\end{itemize}

Практика направлена на закрепление навыков работы в Linux-среде, разработки на языке Си, управления зависимостями и сборкой проектов, а также на исследование производительности программ при различных подходах к линковке.

Однако аутентифиакция (процесс подтверждения личности пользователя) по паролю имеет множество недостатков.
Если пароль недостаточно сложный, то его можно подобрать перебором, а если же пароль сложный и уникальный, то его трудно запомнить.
Существует еще недостатки, поэтому, чтобы избежать неприятностей мы будем использовать авторизацию с помощью SSH.

SSH (Secure Shell, <<безопасная оболочка>>) -- сетевой протокол для защищенного удаленного доступа к системе. Протокол обеспечивает шифрование соединения и проверку подлинности обеих сторон. SSH дает возможность подключиться к удаленному серверу и выполнять команды в терминале так же, как если бы использовалось локальное подключение на той же машине.

Для подключения к виртуальной машине с помощью встроенного SSH-клиента была выполнена настройка проброса портов (Port Forwarding):
\begin{itemize}
    \item Тип подключения: NAT -- режим сети, при котором виртуальная машина использует IP-адрес физического компьютера для выхода в интернет;
    \item Протокол: TCP -- протокол управления передачей данных, который обеспечивает надёжное, установленное и упорядоченное соединение между ВМ и компьютером;
    \item Адрес хоста: 127.0.0.1;
    \item Порт хоста: 2222;
    \item Порт гостя: 22.
\end{itemize}

\begin{figure}[H]
  \centering
  \includegraphics[height=2cm]{host.jpg}
  \caption{\small Проброс портов}
\end{figure}

Далее необходимо было сгенерировать пару ключей и публичный ключ скопировать на виртуальную машину.
Принцип работы SSH-ключей основан на асимметричном шифровании. Приватный ключ шифрует данные. Обратное преобразование может выполнить только связанный с ним публичный ключ. 
\begin{verbatim}
ssh-keygen -t rsa -b 4096
ssh-copy-id -p 2222 tashlykova@127.0.0.1
ssh -p 2222 tashlykova@localhost 
\end{verbatim}

Благодаря этим действиям подключение к ВМ осуществляется без ввода пароля. Засчет такой аутентификации мы получаем стойкость к взлому, так как полный перебор всех возможных SSH-ключей невозможен даже с помощью сверхмощных современных компьютеров. Также приватный ключ никогда не покидает машину пользователя и не передается по сети, поэтому украсть его через сеть невозможно. Ключи не нужно запоминать, а одну пару можно использовать для доступа к своим разным серверам. Это дает нам удобство, гибкость и надежность при работе.

Для этого построим рекурсивное дерево зависимостей. Для наглядности был разработан скрипт $tree.sh$.

\begin{minted}[fontsize=\footnotesize]{c}
#tree.sh 
function print_deps() {
    local file=$1
    local indent=$2
    local first=$3
    if [ ! -f "$file" ]; then
        echo "${indent}[НЕ НАЙДЕНО: $file]"
        return
    fi
    ldd "$file" 2>/dev/null | while read line; do
        if echo "$line" | grep -q "linux-vdso"; then
            continue
        fi
        if echo "$line" | grep -q "=> /"; then
            lib=$(echo "$line" | awk '{print $3}')
            name=$(basename "$lib")
            echo "${indent}|-- $name"
            print_deps "$lib" "${indent}|   " "no"
        elif echo "$line" | grep -q "^/lib/ld-linux"; then
            lib=$(echo "$line" | awk '{print $1}')
            name=$(basename "$lib")
            echo "${indent}|__ $name"
            print_deps "$lib" "${indent}    " "no"
        fi
    done
}
print_deps "$1" "" "yes"
\end{minted}

{\centering\subsection{Разработка статических и динамических библиотек}}
В индивидуальном задании №1 было необходимо создать библиотеку с реализацией функции, которая проверяет является ли указанное слово палиндромом, при этом она должня быть реализована различными способами: с рекурсией и без рекурсии, также в реализации запрещалось использовать библиотечные функции.
Для этого я написала две основные функции $palindrome$, $palindrome\_recursive$ -- итеративная и рекурсивная реализация, а так же одну вспомогательную функцию $string\_len$, для вычисления длины строки.
\begin{minted}[fontsize=\footnotesize]{c}
#ifndef PALINDROME_H
#define PALINDROME_H

#include <stdbool.h>

bool palindrome(char *string, int n);
bool palindrome_recursive(char *string, int n);
int string_len(char *string);

#endif
\end{minted}

{\bf{Алгоритм $palindrome$}}: сравниваются символы с начала и конца строки, постепенно сдвигаясь к центру. При обнаружении несовпадающей пары возвращается false. Время работы O(n/2), память O(1).

{\bf{Алгоритм $palindrome\_recursive$}}: базовый случай -- пустая строка или строка из одного символа являются палиндромами. Иначе сравниваются первый и последний символы строки; при совпадении выполняется рекурсивный вызов для подстроки без крайних символов. Время работы O(n), память O(n).\\
Исходный код приведен в Приложении А.

Для управления сборкой библиотек и тестовых программ использовалась мета-система сборки CMake. Структура проекта выглядит следующим образом:

Статическая библиотека -- это коллекция объектных файлов (.o), объединенных в один архивный файл. Во время компиляции программы, использующей статическую библиотеку, компоновщик (linker) копирует весь необходимый код из библиотеки в исполняемый файл. Таким образом, исполняемый файл становится самодостаточным и не зависит от наличия библиотеки в системе во время выполнения.

Динамическая (разделяемая) библиотека -- это коллекция скомпилированного кода, который загружается в память программы во время запуска. Исполняемый файл содержит только ссылки на функции и данные этой библиотеки, а не их копии. Это позволяет нескольким программам использовать одну и ту же копию библиотеки в памяти.

Настройка сборки библиотек в $src/CMakeLists.txt$:
\begin{minted}[fontsize=\footnotesize]{c}
# Статическая библиотека
add_library(palindrome_static STATIC ${LIB_SOURCES})
set_target_properties(palindrome_static PROPERTIES
    OUTPUT_NAME palindrome
)

# Динамическая библиотека
add_library(palindrome_shared SHARED ${LIB_SOURCES})
set_target_properties(palindrome_shared PROPERTIES
    OUTPUT_NAME palindrome
    VERSION ${PROJECT_VERSION}
    SOVERSION 1
)
\end{minted}

При обычной компоновке с динамической библиотекой, ОС автоматически загружает все необходимые библиотеки при запуске программы. Если какая-либо из них отсутствует, программа не запустится.

Однако существует еще более гибкий механизм работы с динамическими библиотеками -- их динамическая загрузка во время выполнения (runtime loading).
Runtime loading предоставляет программисту полный контроль над процессом, это означает, что программа может решить, какую библиотеку загрузить и какие функции из нее использовать, не на этапе компиляции, а уже в процессе своей работы.
Для реализации этого механизма в Unix/Linux используется набор функций, предоставляемых библиотекой dl (dynamic linking library)

Для загрузки библиотеки во время выполнения использованы функции dlopen() и dlsym():
\begin{minted}[fontsize=\footnotesize]{c}
void *handle = dlopen("libpalindrome.so", RTLD_LAZY);
palindrome_func_t func = (palindrome_func_t)dlsym(handle, "palindrome");
\end{minted}

{\centering\subsection{Исследование разделяемых библиотек}}
Как происходит тестирование функций $palindrome$ и $palindrome\_recursive$:
\begin{enumerate}
    \item Генерируются случайные строки заданной длины;

    \item Для каждой строки вычисляется длина с помощью $string\_len$;

    \item Выполняется проверка на палиндром (итеративная или рекурсивная);

    \item Измеряется процессорное время с помощью $clock()$;

    \item Результат усредняется по количеству итераций.
\end{enumerate}
Тестирование проходит для каждого типа линковки библиотеки.
Также дополнительно разработан скрипт для автоматического тестирования всех флагов оптимизации:
\begin{itemize}
    \item -O0 -- без оптимизации (режим отладки)
    \item -O1	-- базовые оптимизации
    \item -O2	-- полная оптимизация (рекомендуемый уровень)
    \item -Os	-- оптимизация по размеру кода
\end{itemize}

Исследуем разделяемые библиотеки в полученной программе, используя команду ldd и построим соответствующие рекурсивные деревья зависимостей.

{\centering\subsection{Двоичные файлы и визуализация в псевдографике}}
Следующий этап научно-исследовательской работы -- разработка программы с использованием псевдографической библиотеки ncurses.

{\bf{Ncurses (<<new curses>>)}} -- это библиотека предназначенная для управления вводом-выводом на терминал. Она позваляет работать с виртуальным экраном, создавать и управлять несколькими окнами на одном терминале, каждое со своим содержимым и атрибутами.

Весь интерфейс построен на основе оконной модели -- каждый экран или диалог представляет собой отдельное окно, что позволяет гибко управлять отображением и обновлением информации.
Для реализации были использованы следующие функций ncurses: 
\begin{itemize}
    \item $initscr()$ -- инициализирует библиотеку ncurses и создает стандартное окно (stdscr), представляющее весь терминал. Вызывается в начале каждой функции, работающей с интерфейсом.
    \item $newwin(height, width, start\_y, start\_x)$ -- создает новое окно заданного размера в указанной позиции. Используется для создания модальных диалогов и меню.
    \item $delwin(win)$ -- удаляет созданное окно и освобождает память.
    \item $box(win, 0, 0)$ -- рисует рамку вокруг окна с использованием символов по умолчанию (ASCII-графика).
    \item $mvwprintw(win, y, x, format, ...)$ -- используется для позиционированного вывода форматированной строки. 
    \item $endwin()$ -- завершает работу с ncurses и восстанавливает терминал в исходное состояние. Вызывается перед выходом из любой функции интерфейса.
    \item $clear()$ -- очищает стандартное окно, удаляя весь предыдущий вывод.
    \item $refresh()$ -- обновляет физический экран, синхронизируя буфер ncurses с реальным терминалом.
\end{itemize}
Приведу пример создания главного дисплея.
\begin{minted}[fontsize=\footnotesize]{c}
WINDOW *main_win = newwin(17, 55, (rows - 17) / 2, (cols - 55) / 2);
box(main_win, 0, 0);
mvwprintw(main_win, 0, 2, " PRODUCT DATABASE MANAGEMENT ");
\end{minted}
Для ввода данных используются функции с поддержкой редактирования:
\begin{itemize}
    \item $wgetch(win)$ -- получает один символ из окна (неблокирующий ввод с обработкой специальных клавиш).
    \item $wgetnstr(win, str, size)$ -- считывает строку текста с клавиатуры.
    \item $echo()$ -- включает отображение вводимых символов на экране.
    \item $noecho()$ -- отключает отображение вводимых символов.
    \item $cbreak()$ -- переводит терминал в режим посимвольного ввода, заставляя терминал передавать каждый введённый символ программе сразу (без буферизации).
    \item $curs\_set(0/1)$ -- управляет видимостью курсора (0 -- скрыт, 1 -- видим).
    \item $wmove(win, y, x)$ -- перемещает курсор в указанную позицию в окне.
    \item $wclrtoeol(win)$ -- очищает строку от текущей позиции курсора до конца.
\end{itemize}

А так же создать структуру описывающую заголовок базы данных, содержащую:
\begin{itemize}

	\item Контрольная сумма (4 байта) -- беззнаковое целое число, контрольная сумма всех данных следующих за заголовком по алгоритму CRC-32 вызываемая из библиотеки zlib.h

Проведем анализ полученных результатов.
Флаг -O0 дает самое медленное выполнение программы, при таком подходе код компилируется без каких-либо оптимизаций, все переменные хранятся в памяти.

Флаг -O1 обеспечивает хороший баланс между временем компиляции и производительностью, время выполнения порграммы немного уменьшается. С таким подходом идет устранение мертвого кода, присутствует оптимизация переходов, имеется начальное распределение переменных по регистрам.

Флаг -O2 дал наилучшую производительность по времени, благодаря развертыванию циклов, оптимизации хвостовой рекурсии, векторизации операций.

Флаг -Os уменьшеает размер исполняемого кода, использует более короткие инструкции. Время выполнения порграммы, так же как и с -O0, медленное.

{\centering\section*{Заключение}}\addcontentsline{toc}{section}{Заключение}
В ходе выполнения летней научно-исследовательской практики были полностью реализованы все поставленные задачи:
\begin{enumerate}
    \item \textbf{Установка и настройка виртуальной среды Debian 12.14, проброс портов, беспарольная SSH-аутентификация}: 
    Установлен Oracle VirtualBox, развернута виртуальная машина с Debian 12.14, настроен проброс 22-го порта для SSH-подключения, сгенерирована пара SSH-ключей и настроена беспарольная аутентификация.

    \item \textbf{Освоение основ работы в командном интерпретаторе}: 
    Изучены базовые команды Linux ($whoami$, $date$, $cal$, $uptime$, $df$, $cp$, $mv$, $touch$, $rm$, $stat$, $file$, $find$, $whereis$, $cat$, $hexdump$, $less$, $grep$, $time$), освоена работа с историей команд, автодополнением и редактированием командной строки.

    \item \textbf{Разработка функции проверки палиндрома, сборка статической и динамической библиотек, реализация линковки через dlopen}: 
    Реализована функция проверки палиндрома в двух вариантах (итеративном и рекурсивном) без использования библиотечных функций; созданы статическая ($libpalindrome.a$) и динамическая ($libpalindrome.so$) библиотеки с использованием CMake; реализована динамическая загрузка библиотеки через $dlopen()$. \textit{Средства разработки: GCC 12.2.0, CMake.}

    \item \textbf{Тестирование скорости работы при флагах оптимизации (O0, O1, O2, Os), сравнение размеров файлов}: 
    Проведено тестирование производительности. Установлено, что флаг $-O2$ обеспечивает максимальную производительность (ускорение до 16\% по сравнению с $-O0$), а $-Os$ дает наименьший размер исполняемого кода (1.8 КБ для статической библиотеки). Разница между статической и динамической линковкой составила менее 1\%.

    \item \textbf{Исследование зависимостей с ldd}: 
    С помощью команды $ldd$ и разработанного скрипта $tree.sh$ построены рекурсивные деревья зависимостей для программ из задания. Выявлено, что все программы зависят от стандартной библиотеки $libc.so.6$ и динамического загрузчика $ld-linux-aarch64.so.1$. Программа с $dlopen$ не показывает зависимость от $libpalindrome.so$ в выводе ldd, так как библиотека загружается во время выполнения.

    \item \textbf{Разработка структур PRICE и заголовка базы данных}: 
    Создана структура $PRICE$ с названием категориии (8 байт, строка Си -- указатель на строку с динамической памятью), названием товара (8 байт, строка Си -- указатель на строку с динамической памятью), цена (8 байт, беззнаковое вещественное число с точностью до двух знаков после запятой), количество (4 байта, беззнаковое целочое число) и заголовок базы данных $DB\_HEADER$ с сигнатурой (4 байта, массив символов char), номером транзакции (4 байта, беззнаковое целое число), количеством записей (4 байта, беззнаковое целое число) и контрольной суммой CRC-32 (4 байта, беззнаковое целое число). Реализованы функции вычисления CRC-32, сохранения и загрузки базы данных в бинарный файл. \textit{Библиотека: zlib.}

    \item \textbf{Разработка приложения с псевдографическим интерфейсом ncurses}: 
    Разработана программа на ncurses с главным меню, позволяющая:
    \begin{itemize}
        \item добавлять товары с посимвольным вводом и валидацией данных;
        \item выполнять поиск по категории с вычислением средней цены товара с максимальным количеством;
        \item просматривать все записи базы данных;
        \item сохранять базу данных в бинарный файл;
        \item просматривать информацию о базе (сигнатура, транзакции, CRC-32).
    \end{itemize}
    Реализована защита от ввода некорректных данных (пустые поля, отрицательные значения, буквы в числовых полях). \textit{Библиотека: ncurses.}
\end{enumerate}

Все задачи, сформулированные в постановке, выполнены в полном объеме. Программный код соответствует требованиям индивидуального варианта №14.
