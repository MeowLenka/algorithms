    \item GCC -- компилятор языка Си;

    \item Nano и Visual Studio Code -- редакторы кода.
\end{itemize}

Практика направлена на закрепление навыков работы в Linux-среде, разработки на языке Си, управления зависимостями и сборкой проектов, а также на исследование производительности программ при различных подходах к линковке.

Далее было необходимо исследовать зависимости между программой командного интерпретатора $/bin/bash$ и динамическими библиотеками операционной системы при помощи команды ldd. Для этого построим рекурсивное дерево зависимостей. Для наглядности был разработан скрипт $tree.sh$.

\begin{minted}[fontsize=\footnotesize]{c}
#tree.sh 
function print_deps() {
    local file=$1
    local indent=$2
    local first=$3
    if [ ! -f "$file" ]; then
        echo "${indent}[НЕ НАЙДЕНО: $file]"
        return
    fi
    ldd "$file" 2>/dev/null | while read line; do
        if echo "$line" | grep -q "linux-vdso"; then
            continue
        fi
        if echo "$line" | grep -q "=> /"; then
            lib=$(echo "$line" | awk '{print $3}')
            name=$(basename "$lib")
            echo "${indent}|-- $name"
            print_deps "$lib" "${indent}|   " "no"
        elif echo "$line" | grep -q "^/lib/ld-linux"; then
            # Загрузчик (ld-linux)
            lib=$(echo "$line" | awk '{print $1}')
            name=$(basename "$lib")
            echo "${indent}|__ $name"
            # У загрузчика нет зависимостей, но можем проверить
            print_deps "$lib" "${indent}    " "no"
        fi
    done
}
print_deps "$1" "" "yes"
\end{minted}

Все программы зависят от libc.so.6 -- стандартной библиотеки языка Си. Больше всего зависимостей у $bin/ls$.

{\centering\subsection{Разработка статических и динамических библиотек}}
В индивидуальном задании №1 было необходимо создать библиотеку с реализацией функции, которая проверяет является ли указанное слово палиндромом, при этом она должня быть реализована различными способами: с рекурсией и без рекурсии, также в реализации запрещалось использовать библиотечные функции.
Для этого я написала две основные функции $palindrome$, $palindrome\_recursive$ -- итеративная и рекурсивная реализация, а так же одну вспомогательную функцию $string\_len$, для вычисления длины строки.
\begin{minted}[fontsize=\footnotesize]{c}
#ifndef PALINDROME_H
#define PALINDROME_H

#include <stdbool.h>

bool palindrome(char *string, int n);
bool palindrome_recursive(char *string, int n);
int string_len(char *string);

#endif
\end{minted}

Алгоритм $palindrome$: сравниваются символы с начала и конца строки, постепенно сдвигаясь к центру. При обнаружении несовпадающей пары возвращается false. Время работы O(n/2), память O(1).\\
Алгоритм $palindrome\_recursive$: базовый случай -- пустая строка или строка из одного символа являются палиндромами. Иначе сравниваются первый и последний символы строки; при совпадении выполняется рекурсивный вызов для подстроки без крайних символов. Время работы O(n), память O(n).\\
Исходный код приведен в Приложении А.

Для управления сборкой библиотек и тестовых программ использовалась мета-система сборки CMake. Структура проекта выглядит следующим образом:

Статическая библиотека -- это коллекция объектных файлов (.o), объединенных в один архивный файл. Во время компиляции программы, использующей статическую библиотеку, компоновщик (linker) копирует весь необходимый код из библиотеки в исполняемый файл. Таким образом, исполняемый файл становится самодостаточным и не зависит от наличия библиотеки в системе во время выполнения.

Динамическая (разделяемая) библиотека -- это коллекция скомпилированного кода, который загружается в память программы во время запуска. Исполняемый файл содержит только ссылки на функции и данные этой библиотеки, а не их копии. Это позволяет нескольким программам использовать одну и ту же копию библиотеки в памяти.

Настройка сборки библиотек в $src/CMakeLists.txt$:
\begin{minted}[fontsize=\footnotesize]{c}
# Статическая библиотека
add_library(palindrome_static STATIC ${LIB_SOURCES})
set_target_properties(palindrome_static PROPERTIES
    OUTPUT_NAME palindrome
)

# Динамическая библиотека
add_library(palindrome_shared SHARED ${LIB_SOURCES})
set_target_properties(palindrome_shared PROPERTIES
    OUTPUT_NAME palindrome
    VERSION ${PROJECT_VERSION}
    SOVERSION 1
)
\end{minted}
При обычной компоновке с динамической библиотекой, ОС автоматически загружает все необходимые библиотеки при запуске программы. Если какая-либо из них отсутствует, программа не запустится.

Однако существует еще более гибкий механизм работы с динамическими библиотеками -- их динамическая загрузка во время выполнения (runtime loading).
Runtime loading предоставляет программисту полный контроль над процессом, это означает, что программа может решить, какую библиотеку загрузить и какие функции из нее использовать, не на этапе компиляции, а уже в процессе своей работы.
Для реализации этого механизма в Unix/Linux используется набор функций, предоставляемых библиотекой dl (dynamic linking library)

Для загрузки библиотеки во время выполнения использованы функции dlopen() и dlsym():
\begin{minted}[fontsize=\footnotesize]{c}
void *handle = dlopen("libpalindrome.so", RTLD_LAZY);
palindrome_func_t func = (palindrome_func_t)dlsym(handle, "palindrome");
\end{minted}

{\centering\subsection{Исследование разделяемых библиотек}}
Как происходит тестирование функций $palindrome$ и $palindrome\_recursive$:
\begin{enumerate}
    \item Генерируются случайные строки заданной длины;

    \item Для каждой строки вычисляется длина с помощью $string\_len$;

    \item Выполняется проверка на палиндром (итеративная или рекурсивная);

    \item Измеряется процессорное время с помощью $clock()$;

    \item Результат усредняется по количеству итераций.
\end{enumerate}
Тестирование проходит для каждого типа линковки библиотеки.
Также дополнительно разработан скрипт для автоматического тестирования всех флагов оптимизации:
\begin{itemize}
    \item -O0 -- без оптимизации (режим отладки)
    \item -O1	-- базовые оптимизации
    \item -O2	-- полная оптимизация (рекомендуемый уровень)
    \item -Os	-- оптимизация по размеру кода
\end{itemize}

{\centering\subsection{Двоичные файлы и визуализация в псевдографике}}
Следующий этап научно-исследовательской работы -- разработка программы с использованием псевдографической библиотеки ncurses.

Ncurses («new curses») -- это библиотека предназначенная для управления вводом-выводом на терминал. Она позваляет работать с виртуальным экраном, создавать и управлять несколькими окнами на одном терминале, каждое со своим содержимым и атрибутами.

В рамках задания было неоходимо реализовать структуру с именем PRICE, содержащую следующие поля:
\begin{itemize}
    \item Название категории (строка Си).
    \item Название товара (строка Си).
    \item Стоимость товара в рублях (вещественный тип).
    \item Количество товаров в наличии (целочисленный тип).
\end{itemize}
А так же создать структуру описывающую заголовок базы данных, содержащую:
\begin{itemize}
	\item Сигнатура формата файла (4 байта) -- содержит первые 4 буквы фамилии латиницей.
	\item Номер транзакции (4 байта) -- целое число, которое должно увеличиваться при каждом обращении к файлу, как при чтении, так и при записи.
	\item Количество структур в файле (4 байта) -- количество структур данных из п.1 следующих за заголовком.
	\item Контрольная сумма (4 байта) -- контрольная сумма всех данных следующих за заголовком по алгоритму CRC-32 вызываемая из библиотеки zlib.h
\end{itemize}

Весь интерфейс построен на основе оконной модели -- каждый экран или диалог представляет собой отдельное окно, что позволяет гибко управлять отображением и обновлением информации.
Для реализации были использованы следующие функций ncurses: 
\begin{itemize}
    \item $initscr()$ -- инициализирует библиотеку ncurses и создает стандартное окно (stdscr), представляющее весь терминал. Вызывается в начале каждой функции, работающей с интерфейсом.
    \item $newwin(height, width, start\_y, start\_x$) -- создает новое окно заданного размера в указанной позиции. Используется для создания модальных диалогов и меню.
    \item $delwin(win)$ -- удаляет созданное окно и освобождает память.
    \item $box(win, 0, 0)$ -- рисует рамку вокруг окна с использованием символов по умолчанию (ASCII-графика).
    \item $mvwprintw(win, y, x, format, ...)$ -- используется для позиционированного вывода форматированной строки. 
    \item $endwin()$ -- завершает работу с ncurses и восстанавливает терминал в исходное состояние. Вызывается перед выходом из любой функции интерфейса.
    \item $clear()$ -- очищает стандартное окно, удаляя весь предыдущий вывод.
    \item $refresh()$ -- обновляет физический экран, синхронизируя буфер ncurses с реальным терминалом.
\end{itemize}
Приведу пример создания главного дисплея.
\begin{minted}[fontsize=\footnotesize]{c}
WINDOW *main_win = newwin(17, 55, (rows - 17) / 2, (cols - 55) / 2);
box(main_win, 0, 0);
mvwprintw(main_win, 0, 2, " PRODUCT DATABASE MANAGEMENT ");
\end{minted}
Для ввода данных используются функции с поддержкой редактирования:
\begin{itemize}
    \item $wgetch(win)$ -- получает один символ из окна (неблокирующий ввод с обработкой специальных клавиш).
    \item $wgetnstr(win, str, size)$ -- считывает строку ввода с поддержкой редактирования (Backspace, ввод).
    \item $echo()$ -- включает отображение вводимых символов на экране.
    \item $noecho()$ -- отключает отображение вводимых символов (используется для меню).
    \item $cbreak()$ -- переводит терминал в режим посимвольного ввода (без буферизации строки).
    \item $curs\_set(0/1)$ -- управляет видимостью курсора (0 -- скрыт, 1 -- видим).
    \item $wmove(win, y, x)$ -- перемещает курсор в указанную позицию в окне.
    \item $wclrtoeol(win)$ -- очищает строку от текущей позиции курсора до конца.
\end{itemize}
Во время ввода текста от пользователя каждый введенный символ отображается сразу. Для цены и количества товара ввод специальных символов запрещен (кроме точки в поле для цены), при попытке ввести запрещенный символ, программа его удаляет.

Были выявлены следующие динамические зависимости:
\begin{itemize}
    \item libncurses.so.6 -- основная библиотека для создания псевдографического интерфейса. Предоставляет все необходимые функции для работы с окнами, вводом и выводом в терминале.
    \item libtinfo.so.6 -- библиотека терминальной информации (terminfo). Обеспечивает корректную работу с различными типами терминалов. Загружается как зависимость libncurses.

    \item ld-linux-aarch64.so.1 -- динамический загрузчик. Отвечает за загрузку и связывание всех динамических библиотек при запуске программы. Является обязательной зависимостью для всех динамически слинкованных программ в Linux.
\end{itemize}

{\centering\section*{Заключение}}\addcontentsline{toc}{section}{Заключение}

В ходе выполнения летней научно-исследовательской практики были полностью реализованы все поставленные задачи:

\begin{enumerate}
    \item \textbf{Установка и настройка среды виртуализации}: установлен Oracle VirtualBox, развернута виртуальная машина с Debian 12 (логин — \texttt{tashlykova}, hostname — \texttt{x7k9m2p4}), настроен проброс 22-го порта для SSH-подключения.

    \item \textbf{Освоение работы в командном интерпретаторе}: изучены базовые команды Linux (\texttt{whoami}, \texttt{date}, \texttt{cal}, \texttt{uptime}, \texttt{df}, \texttt{cp}, \texttt{mv}, \texttt{touch}, \texttt{rm}, \texttt{stat}, \texttt{file}, \texttt{find}, \texttt{whereis}, \texttt{cat}, \texttt{hexdump}, \texttt{less}, \texttt{grep}, \texttt{time}), освоена работа с историей команд, автодополнением и редактированием командной строки, настроена беспарольная SSH-аутентификация по ключам.

    \item \textbf{Разработка статической и динамической библиотек}: реализована функция проверки палиндрома в двух вариантах (итеративном и рекурсивном) без использования библиотечных функций; созданы статическая (\texttt{libpalindrome.a}) и динамическая (\texttt{libpalindrome.so}) библиотеки с использованием CMake; реализована динамическая загрузка библиотеки через \texttt{dlopen()}.

    \item \textbf{Тестирование производительности}: проведено тестирование скорости работы функций при различных флагах оптимизации компилятора (\texttt{-O0}, \texttt{-O1}, \texttt{-O2}, \texttt{-Os}). Установлено, что флаг \texttt{-O2} обеспечивает максимальную производительность (ускорение до 16\% по сравнению с \texttt{-O0}), а \texttt{-Os} дает наименьший размер исполняемого кода. Разница между статической и динамической линковкой составила менее 1\%.

    \item \textbf{Исследование разделяемых библиотек}: с помощью команды \texttt{ldd} и разработанного скрипта \texttt{tree.sh} построены рекурсивные деревья зависимостей для программ из задания. Выявлено, что все программы зависят от стандартной библиотеки \texttt{libc.so.6} и динамического загрузчика \texttt{ld-linux-aarch64.so.1}. Программа с \texttt{dlopen} не показывает зависимость от \texttt{libpalindrome.so} в выводе ldd, так как библиотека загружается во время выполнения.

    \item \textbf{Разработка программы с псевдографическим интерфейсом}: создана структура \texttt{PRICE} (категория, название, цена, количество) и заголовок базы данных с сигнатурой, номером транзакции, количеством записей и контрольной суммой CRC-32. Разработана программа на ncurses с главным меню, позволяющая добавлять товары, выполнять поиск по категории с вычислением средней цены товара с максимальным количеством, просматривать все записи, сохранять базу данных и просматривать информацию о базе. Реализована защита от ввода некорректных данных.
\end{enumerate}

В ходе работы были изучены и освоены следующие технологии и навыки:
\begin{itemize}
    \item Работа с виртуальными машинами и настройка сетевого доступа (проброс портов);
    \item Командная строка Linux и основные утилиты;
    \item Системы сборки \texttt{CMake} и \texttt{make};
    \item Создание и использование статических и динамических библиотек;
    \item Загрузка библиотек во время выполнения (\texttt{dlopen}, \texttt{dlsym});
    \item Исследование зависимостей программ с помощью \texttt{ldd};
    \item Работа с двоичными файлами и контрольными суммами CRC-32;
    \item Создание псевдографических интерфейсов с библиотекой \texttt{ncurses};
    \item Оптимизация кода с использованием флагов компилятора;
    \item Документирование результатов экспериментов.
\end{itemize}

Средства разработки и инструментарий:
\begin{itemize}
    \item ОС: GNU/Linux Debian 12 (гостевая), Ubuntu (хостовая);
    \item Компилятор: GCC 12.2.0;
    \item Система сборки: CMake 3.25+ и Make;
    \item Отладка и разработка: Nano, Visual Studio Code;
    \item Библиотеки: ncurses, zlib;
    \item Скрипты автоматизации: Bash.
\end{itemize}

Все задачи, сформулированные в постановке, выполнены в полном объеме. Результаты экспериментов воспроизводимы: разработанные скрипты \\
\noindent \texttt{test\_optimization.sh} и \texttt{analyze\_libs.sh} позволяют повторить все измерения на системе с аналогичным окружением. Программный код соответствует требованиям индивидуального варианта №14.
